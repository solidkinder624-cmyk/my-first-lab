# ドミノ・クラッシュ PvP (Domino Crash)

千数百個のブロックで組まれた建造物の**弱点を見極めて叩き、連鎖崩壊させる速さ**を
競う Roblox のマルチプレイ。全員が同じ構造物を1つずつ持ち、先に100%崩し切った
方が勝つ。1試合は最長60秒。

```
壁を叩く   → その場の数枚が砕けるだけ。上の階はびくともしない
柱を叩く   → 爆発半径が2.4倍になり、支えを失った上層が丸ごと落ちてくる
足元を叩く → 荷重経路が地面から切れる。そこから上は全部道連れ
```

3Dモデル・テクスチャ・音源アセットを一切使わず、Part と手続き生成だけで成立させている。

## 遊び方 (操作)

| 入力 | 動作 |
|---|---|
| `W` `A` `S` `D` | 移動 |
| クリック / タップ | ハンマーを振る (クールダウン 0.35秒) |
| マウス | 照準。画面中央から 22 studs のレイが飛ぶ |

構造物はラウンドごとに巡回する。

| 構造物 | 特徴 | 弱点 |
|---|---|---|
| **塔 (Tower)** | 約2200個。柱が格子状に立つラーメン構造の段塔 | 外周の柱。奥のコア柱は外壁を崩さないと届かない |
| **要塞 (Fortress)** | 約1000個。城壁 + 四隅の櫓 + 門 | 門の上のまぐさ石。櫓は足元の4本柱 |
| **水道橋 (Aqueduct)** | 約1100個。橋脚と桁だけ | 橋脚。1本折ると両隣の径間ごと落ちる |

## 動かす

このリポジトリには **ソースだけ** が入っている (`.rbxl` はバイナリなので Git と相性が悪い)。
[Rojo](https://rojo.space/) で Studio に同期する。

```bash
# 1. ツールを入れる (rokit: https://github.com/rojo-rbx/rokit)
rokit install

# 2. 同期サーバを起動
rojo serve roblox/domino-crash/default.project.json

# 3. Roblox Studio で新規 Baseplate を開き、Rojo プラグインの Connect を押す
#    → ReplicatedStorage / ServerScriptService / StarterPlayerScripts に反映される

# 4. Studio の Test タブ → Players を2以上にして "Start" (ローカルサーバで対戦を検証)
```

`rojo build roblox/domino-crash/default.project.json -o DominoCrash.rbxl` で
`.rbxl` を書き出して直接開くこともできる。

## Studio を開かずに検証する

ゲームの中核 (`Config` / `Blueprint` / `Collapse` / `Progress` / `HitRules`) は
Roblox API を一切参照しない純関数として書いてあり、
[Luau CLI](https://github.com/luau-lang/luau/releases) だけで実行できる。

```bash
cd roblox/domino-crash && luau verify.luau     # 117 項目
```

検査しているのは、Studio で目視しても気付きにくい種類のことだけ:

| 検査 | なぜ必要か |
|---|---|
| 生成直後に1個も落ちない | 片持ち限界を1でも超えたブロックがあると、試合開始と同時に勝手に崩れる |
| ブロック同士がめり込んでいない | めり込みは物理エンジンの反発を呼び、置いた瞬間に構造物が跳ねる |
| 詰め物を全部消しても骨組みが立つ | 「壁を叩いても崩れない」というルールがコード上で本当に成立しているか |
| 柱を叩くと詰め物の3倍以上崩れる | 弱点の見極めが実際にリターンになっているか (現状 10〜30倍) |
| 天辺を叩いても8%未満 | 適当に高い所を叩くのが近道になっていないか |
| 地上から届く打撃だけで100%まで崩せる | 手の届かない高さに浮遊ブロックが取り残されると決着がつかない |
| 7〜14手で決着する | 60秒の制限時間に対して短すぎず長すぎないか |
| 同じシードで完全同一の構造物 | 対戦相手と同じ物を壊しているか (公平性) |
| リーチ改造・連打マクロを弾く | チート対策が実際に効いているか |

`.github/workflows/domino-crash-verify.yml` が push ごとにこれを実行する。

## 設計

### 「何が崩れるか」を物理エンジンに決めさせない

素朴に作ると「叩いた点の半径 R のブロックの `Anchored` を false にする」になるが、
これだと**宙に浮いた壁がその場に残る**絵になり、ドミノ崩しの快感が出ない。

そこで荷重の伝わり方を `Collapse.luau` が明示的に持っている。トラスの粗い近似:

```
荷重を伝えるブロック (柱・床) の真上に乗っている  … 荷重経路コスト 0
同じ高さで横に繋がっている                        … 片持ち。コスト +1
地面に接している                                  … コスト 0 の起点

コストが maxCantilever (=4) を超える / どこからも到達できない → 自重で落ちる
```

打撃のたびに、この経路を接地ブロックから 0-1 BFS (Dial のバケット法) で引き直し、
**到達できなくなったブロックを全部まとめて崩す**。柱を1本折ると、その柱が
支えていた範囲が張り出し限界を超え、上のフロアが落ち、その上がまた支えを失う。
「全パーツ一斉爆破」はこの再計算の副産物として出てくる。

### 壁は荷重を伝えない

弱点の見極めがゲームになるのは、`Config.build.bearingKinds` で
**壁 (Wall) だけが「上を支えられない詰め物」になっている**から。

* 壁を叩く → 数枚砕けて終わり。上の階の荷重経路は柱を通っているので無傷
* 柱を叩く → 爆発半径が `keyPartBonus` 倍 (2.4倍) に広がり、隣の柱まで巻き込む

柱は色と材質をはっきり変えてある (`Config.appearance`)。これは演出ではなく仕様で、
どれが柱か見て分からないと弱点探しがただの運になる。

構造物は柱の間隔 (`pillarEvery`) と片持ち限界 (`maxCantilever`) の関係で
成り立っている。`maxCantilever >= pillarEvery` を割ると、柱で囲まれた升目の中心が
生成直後に落ちる。verify.luau がこの不変条件を直接検査している。

### 数千個の物理パーツを捌く

| 対策 | 実装 |
|---|---|
| アンカー解除を分割する | 1フレームあたり `unanchorBudget` (140個) まで。打撃点から近い順に外すので、副作用として崩壊が波紋状に広がって見える |
| 衝突ペアを抑える | 同時に動く破片が `noCollideAbove` (400個) を超えたら、以降の破片は `CanCollide = false` で落とす。衝突コストは個数の2乗で効く |
| 破片を貯めない | 落ちきった / `debrisLifetime` (5秒) 過ぎた / `maxActiveParts` (900個) を超えた破片は即消去 |
| Part の生成コストを隠す | 構造物は1組だけ作って人数ぶん `Clone`。次ラウンドぶんは結果表示中に先読みして作る |
| 触らないものは切る | 全ブロックが `CanTouch = false` / `CastShadow = false`。崩れた破片は `CanQuery = false` (ハンマーのレイに映らない) |
| 物理を分散する | 破片の `SetNetworkOwner` をその構造物の持ち主へ。4人対戦なら4台のクライアントに物理が散る |
| 瓦礫でプレイヤーを吹き飛ばさない | 破片専用の衝突グループを作り、プレイヤー (Default) とは衝突させない。床は構造物側のグループに入れてあるので瓦礫は床に積もる |

### 崩壊率を毎フレーム数えない

`GetPartsInPart` も、数千個への `Touched` も使わない。必要な3つの数はサーバが既に持っている:

* `total` … 生成時に確定
* `fallen` … 破片を消すときに +1
* `free` … アンカーが外れてまだ落ちきっていない数 (`freedCount - fallen`)

```
崩壊率 = (fallen + free * 0.35) / total * 100
```

空中のブロックを 0.35 で数えるのが味付けで、柱を折った瞬間に上層が丸ごと free に
なるため、**瓦礫が床に着く前にゲージが跳ねる**。操作とゲージの反応の間に落下時間が
挟まらない。走査するのは「いま動いている破片」だけ (上限900個)、送信は 0.2 秒に1回、
全員ぶんを1パケットにまとめて。

### 演出はサーバを介さない

サーバが送るのは `{ slot, position, keyHit, direct, chain }` の数個の数字だけ。
粉塵・火花・カメラ揺れは各クライアントがローカルに生成する。パーティクルを
サーバで作ると、4人 × 毎秒6打撃ぶんのインスタンス生成がレプリケーションに乗って
全員が同時にカクつく。

* **ヒットストップ** … Roblox にタイムスケールが無いので、0.05秒だけカメラの CFrame を
  掴んで固定することで代用する。世界は動き続けているのに視点だけ止まるので、
  打撃の瞬間だけ時間が詰まったように見える
* **カメラシェイク** … trauma 方式。揺れを `trauma^2` に比例させると小さい揺れが静かに
  なる。`math.random` ではなく `math.noise` を使うのは、乱数だと1フレームごとに飛んで
  「震え」ではなく「ちらつき」に見えるため
* **振りのモーション** … `Animation` はアセット ID を要求するので使えない。
  `Tool.Grip` を直接動かすと Roblox が `RightGrip` の Weld を追従させてくれる
* ハンマーの火花だけは**サーバの返事を待たずに**出す。往復ぶん (体感 60〜150ms)
  遅れると、それだけで手応えが消える

### チート対策

クライアントが送れるのは「この Part をここで叩いた」という主張だけ。
何が壊れるかを決めるのはサーバなので、`HammerController.luau` を改造しても
壊せる範囲は1ミリも増えない。サーバ側で弾いているのは:

| 条件 | 防ぐもの |
|---|---|
| 距離 > `reach + graceDistance` | リーチ改造・テレポート |
| クールダウンの90%が経過していない | 連打マクロ |
| 直近1秒の打撃数が `maxHitsPerSecond` 以上 | 上の抜け道 (二重の網) |
| 叩いた Part が自分の構造物ではない | 他人の構造物を壊す妨害 / 自分の進行度の水増し |
| 着弾点が Part の表面から離れている | 座標の捏造 |
| そのブロックが既に崩れている | 同じブロックの二度取り |

弾いた打撃には**何も返さない**。理由を返すと「どこまでなら通るか」を総当たりで
探る材料になる。判定条件そのものは `HitRules.luau` (純ロジック) にあり、
verify.luau が同じコードを直接叩いて検査している。

## 既知の割り切り

* **破片の落下は持ち主のクライアントが計算する。** 物理負荷を分散する代わりに、
  改造クライアントは「既にアンカーが外れたブロック」を早く着地させられる。
  アンカーを外すかどうかはサーバが決めるので水増しできる上限は決まっていて、
  実際の利得は落下時間ぶん (1〜2秒) のゲージだけ。分散を止めたい場合は
  `StructureManager.release` の `SetNetworkOwner` を消せば全部サーバ計算になる。
* **ハンマーの振りは本人の画面にしか出ない。** `Tool.Grip` をクライアントで
  動かしているため。他人にも見せるならサーバ側で動かす必要がある。
* **verify.luau の手数は下限値。** 「高さ22 studs 以内のブロックは全部狙える」と
  仮定して数えているので、実際は外壁が邪魔でコア柱に届かないぶんだけ手数が増える。
  遮蔽を数えていないのは、レイキャストの再現が純ロジックの範囲を超えるため。
* **音は鳴らない。** 外部アセット0本の方針のため。`Config.juice.sounds` に
  `rbxassetid://` を入れれば打撃音・崩壊音・勝利音が鳴る。

## ファイル

```
src/shared/     Roblox API 非依存の純ロジック (verify.luau が直接 require する)
  Config        全チューニング値。サーバ・クライアント・検証器が同じ値を共有
  Blueprint     構造物の手続き生成 (座標とサイズと役割の配列を返すだけ)
  Collapse      支持グラフ・連鎖崩壊の判定・インパルスの計算
  Progress      崩壊率と勝者判定の算術
  HitRules      打撃の受理条件 (距離・クールダウン・レート制限)
  Net           リモートの定義 (ここだけ Roblox 依存)

src/server/
  init.server   配線
  GameManager   試合サイクル・タイマー・勝敗判定・スロット割り当て
  StructureManager  Part の生成/Clone・アンカー解除の分割実行・瓦礫の回収
  HitValidation 打撃リクエストの検証
  ProgressTracker   崩壊率の集計と同期
  ArenaBuilder  床・飛散防止フェンス・衝突グループ・ロビー
  HammerTool    ハンマー (Part だけで組む)

src/client/
  init.client   配線
  Controller/HammerController  入力・レイキャスト・振りのモーション
  Controller/CameraEffects     ヒットストップ・カメラシェイク・FOV パンチ
  UI/HUDController             崩壊率ゲージ・タイマー・相手の進捗
  Effects                      粉塵・火花・音 (すべてローカル生成)
```
